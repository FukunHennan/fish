# 项目结构整理建议

## 当前模块边界

- `controller/`：Go 服务及 `frontend/` React 正式界面。
- `vision/`：Python 摄像头、识别与控制服务。
- `firmware/`：设备固件。
- `protocol/`：跨模块协议。
- `config/`、`scripts/`：配置与部署脚本。
- `docs/`：维护和使用文档。
- `design/gui/prototypes/`：设计原型，不能作为生产入口。

## 优先整理事项

1. 统一前端开发入口。目前 README 和部署文档仍引用 `controller/frontend/gui-redesign-demo/`，应统一为正式前端目录后再移除兼容入口。
2. 将 `layout-demo.html` 等模拟原型统一归档至 `design/gui/prototypes/`，更新链接后再移除重复副本。Figma 捕获页与真实应用入口分开管理。
3. 整理 `console-theme.css` 中连续追加的覆盖规则，按公共布局、组件、响应式分区，保留视觉回归检查。
4. 明确生成文件：前端 dist、二进制、诊断运行记录和缓存不与手写源码混放；Go 嵌入的 `internal/web/dist` 仍须由构建流程生成，不能直接删掉。
5. 每次仅移动一类文件，修正 import、Vite root、脚本工作目录和文档链接，再构建验证。

## 工具选择

本机文件搜索、Git 和构建工具可以完成上述工作；文件管理 MCP 仅作为辅助。当前可调用的 Remote Desktop Commander 有目录浏览能力，但使用前必须确认它连接的设备确实是此项目所在电脑。无需为项目规范化单独安装未经确认的 MCP。

## 本轮视频行为

首次选择优先匹配 `Global Shutter Camera` 名称，保留用户明确选择和已运行会话的摄像头。GUI 编号不固定。

本机预览开关仅挂载或卸载当前页面的视频连接，不删除共享会话。摄像头选择、曝光、识别仍属于服务器共享设置。关闭所有浏览器预览不会自动停止后端采集。旧客户端必须刷新才能获得新行为。

实施状态与后续约束见 [项目维护规范](项目维护规范.md)。旧 mock 脚本和样式已归档；活跃兼容入口和现有预览页面暂时保留。
