# Pro1 代码结构

Pro1 在项目顶层按职责分为 Go 控制器、Python 视觉、ESP32 固件、协议、部署脚本和文档。以下说明当前实际目录；它不要求移动运行代码。

| 目录 | 当前职责 | 主要入口 |
| --- | --- | --- |
| `controller/` | Go Web/API、设备连接与控制权、视觉服务代理、正式赛事前端 | `cmd/fish-controller/main.go` |
| `vision/` | 摄像头采集、识别、跟踪、导航、视频与视觉控制计算 | `server.py`；独立桌面入口在 `main.py` |
| `firmware/` | ESP32-C3 Wi-Fi、设备协议、运动、遥测、配网和 OTA | `src/main.cpp`、`platformio.ini` |
| `protocol/` | ESP32 与 Go 的 v2 通信约定 | `README.md` |
| `config/` | 三个手动配置入口 | `firmware.json`、`program.json`、`tunnel.json` |
| `scripts/` | 按系统启动、Windows 监督与接管、上传辅助 | `start.bat`、`start.sh` |
| `design/` | 页面原型和设计材料，不是正式服务入口 | `gui/prototypes/` |
| `docs/` | 操作、环境、硬件、相机和架构说明 | `README.md` |

## Go 控制器

`controller/internal/` 已按功能拆为 `config`（部署配置）、`diagnostics`（诊断）、`discovery`（局域网发现）、`hub`（设备状态与出站命令）、`identity`（认证证明）、`visionprocess`（Python 进程生命周期）、`visionproxy`（视觉代理）和 `web`（HTTP、WebSocket、账号、控制权、赛事）。正式页面由 `controller/frontend/competition.html` 与 `public/competition/` 构成，并通过 Vite 构建后嵌入 Go；`frontend/src/` 中的 React 页面是历史实验代码，其 JavaScript 测试仍可运行。

## Python 视觉

`vision/` 目前是平铺的 Python 模块，按文件名区分功能：

- 采集和画面处理：`camera_stream.py`、`camera_policy.py`、`crop_region.py`、`video_transform.py`、`interface.py`。
- 识别与控制：`perception.py`、`tracking_application.py`、`navigation.py`、`control.py`、`control_coordinates.py`。
- 服务和会话：`server.py`、`service.py`、`session.py`、`workspaces.py`、`web_api.py`、`web_actions.py`、`webrtc.py`、`recording.py`。
- 界面与配置：`main.py`、`ui.py`、`config.py`、`assets/`；对应测试在 `tests/`。

这种平铺结构已经按文件功能命名，但未形成子包。模块之间使用同目录导入；若后续移动文件，需要同步调整入口、导入、测试和服务启动路径，不能只移动目录。

## ESP32 固件

`firmware/src/` 和 `firmware/include/` 依 PlatformIO 的源码/头文件约定平铺；文件名分别对应网络、发现、认证、运动、舵机、电池和状态灯。`firmware/test/` 已按测试主题分目录；构建配置在 `platformio.ini`。需要按功能继续拆层时，应与 PlatformIO 构建和设备端测试一起完成。

配置位置见[配置文件说明](../../config/README.md)，文档分类见[文档导航](../README.md)。
