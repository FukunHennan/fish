# 概述：架构、目录与整理规范

## 系统架构

```text
浏览器赛事界面 ──HTTP/SSE/WebRTC──> Go 控制器 :8081
                                      ├──WebSocket/UDP──> ESP32 机器鱼
                                      └──本机 HTTP──> Python 视觉服务 :8091
                                                        └──USB 2.0 相机
```

浏览器只访问 Go 控制器；Go 管理账号、设备、控制权和视觉代理；Python 负责摄像头、识别和视觉控制。详见[架构图](technical-architecture.svg)及[代码结构](代码结构.md)。

赛事账号通过同一正式入口登录，Go 根据账号身份提供裁判或选手操作。已结束比赛的比分、用时、事件时间线和录像信息由控制器写入比赛记录；赛事状态流转与记录持久化由控制器负责。

## 文件系统结构

| 路径 | 职责 |
| --- | --- |
| `controller/` | Go 控制器和正式赛事前端 |
| `vision/` | 相机采集、识别、跟踪、导航和视频 |
| `firmware/` | ESP32 固件、构建与测试 |
| `config/` | 三个手动部署配置和一个按 MAC 自动维护的设备运动配置 `device-motion.json` |
| `protocol/` | 设备通信协议 |
| `scripts/` | 新电脑依赖安装、启动、监督、构建和文档检查脚本 |
| `docs/程序/` | 启停、配置、构建、运行行为 |
| `docs/硬件/` | ESP32、相机、接线和产品资料 |
| `docs/概述/` | 架构、目录与整理规范 |

## 整理标准

1. **一处定义，一处说明。** 手动部署参数只进入 `config/` 的三个 JSON；设备运动参数统一进入 `device-motion.json`。组件中的代码默认值和依赖清单不重复成为日常配置入口。
2. **按职责放文件。** 控制器、视觉、固件、协议分别放在对应目录；公众号等独立项目不混入 Pro1。
3. **文档按读者目的归类。** 操作与调参归“程序”，器件事实归“硬件”，跨组件结构归“概述”。同一事实在多处出现时链接主文档，避免复制多份。
4. **改代码时同步相应文档。** 启动、配置、接口、目录或硬件行为变化，应更新对应分类。开发日志只保存在本机，不作为 Git 推送内容。Git 检出后运行 `scripts/docs/install-doc-hooks.ps1` 安装推送前检查；GitHub Actions 在每次推送后重复检查。
5. **保持可核对。** 文档注明实测、厂家资料或代码推断；使用相对链接，移动文件时修正引用。尚未在实机验证的结论明确标注，不写成既成事实。

推送校验只检查随源码变化的程序、硬件和概述文档；诊断日志与归档仅保存在本机。
