# 项目统一参数

更新时间：2026-09-04

## 1. 服务端口

| 参数 | 值 | 说明 |
|---|---:|---|
| GUI | `8098` | 电脑端 React/Vite 页面 |
| Go Controller | `8081` | API、设备 WebSocket、权限和视觉代理 |
| Python Vision | `8091` | 仅监听 `127.0.0.1` |
| Python MJPEG | `8090` | 视觉服务内部视频回退端口 |
| 平板遥测 | `9998` | Python 视觉服务使用 |

公网只应通过 FRP 转发 Go Controller，不应转发 Python 端口或 ESP32 端口。

## 2. 设备通信

| 参数 | 值 | 说明 |
|---|---:|---|
| 协议 | WebSocket + UTF-8 JSON | ESP32 连接 Go 的 `/ws/device` |
| 协议版本 | `1` | 注册消息中的 `protocolVersion` |
| 设备身份 | MAC 地址 | 作为 `deviceId` |
| 控制器心跳 | 约 1 秒 | Go → ESP32 |
| ESP32 状态上报 | 约 1 秒 | ESP32 → Go |
| Go 设备离线判断 | 3 秒 | 超时后移除设备并通知 GUI |
| ESP32 控制器心跳超时 | 3000 ms | 超时后停止并断开 |
| 局域网发现周期 | 3 秒 | ESP32 广播 `device.announce` |

## 3. 运动参数

| 参数 | 默认/范围 | 说明 |
|---|---:|---|
| 默认频率 | `2.5 Hz` | 由 GUI/控制器使用 |
| 频率范围 | `0.3–5.0 Hz` | 控制器整理后下发 |
| 手动默认幅度 | `40%` | 按设备标定和动作换算；默认标定下前进为 `18°` |
| 视觉 PID 巡航幅度基准 | `28°` | Python 随距离调整，再由 Go 限幅，不是固定下发值 |
| 幅度范围 | `0–90°` | 控制器整理后下发 |
| 偏置 | `-90°–+90°` | 根据设备标定范围处理 |
| 动作 | `forward` / `left` / `right` / `stop` / `idle` | 统一动作名称 |
| 设备模式 | `0–4` | `0=停止，1=待机，2=前进，3=左转，4=右转` |

控制器负责参数裁剪和每台设备的标定适配。设备收到有效命令后直接执行，并回报实际状态。

手动、键盘实时、视觉运动和视觉向前标定使用同一限幅流程：先按动作计算振幅，再将 `straightCenter + bias` 限制在 `servoMin` 与 `servoMax` 之间，最后缩小振幅，使整个摆动周期都位于该范围。显式传入 `bias` 也必须经过此检查；中心到达边界时，可用振幅为零。`stop` 使用零振幅、零偏置。

旧标定没有 `servoMin` / `servoMax` 时，以 `0°–180°` 为边界。Go 的 `straightCenter`（旧标定为 `centerDeg`）必须与固件保存的舵机中位一致；本次限幅是控制器参数层的保障，不替代设备中位同步和实机验证。固件目前不独立执行标定范围限幅。

## 4. 视觉和视频

| 参数 | 值 | 说明 |
|---|---:|---|
| 采集尺寸 | `640×480` | Python/OpenCV |
| 目标帧率 | `30 FPS` | 实际值以摄像头状态为准 |
| YOLO 模型 | 可选 `.pt` 文件 | 从 GUI 选择，Python 加载 |
| 视频优先级 | WebRTC | 低延迟优先 |
| 视频回退 | MJPEG | WebRTC 不可用时使用 |
| MJPEG 质量 | `50` | 兼容回退 |
| 视觉控制间隔 | 约 `100 ms` | Python 计算并提交运动意图 |
| 视觉运动命令有效期 | `3 s` | 从 Go 接受该命令开始计时；新运动命令续期，设备心跳不续期 |
| 视觉超时检查间隔 | `100 ms` | 到期后通过设备发送队列提交停止，不等待 Python 或设备 ACK |
| 视觉向前标定时长 | 默认 `3200 ms`，可选 `1–5000 ms` | `durationMs` 控制一次预设运动的有效期，到期自动提交停止 |

视觉命令超时保护在登录认证开启和关闭时均生效。尚未写出的过期视觉命令会被丢弃；正常手动运动、明确停止或 OTA 命令取代视觉运动后，旧视觉计时不再干扰新操作。设备 WebSocket 单次写入最多等待 1 秒，写入失败后关闭连接，依靠固件已有的断线/心跳超时保护停止。

这里的 `3 s` 是 Go 提交停止的命令有效期，不是已验证的物理停机时间，也不是独立视觉会话心跳。真实停机还涉及调度、网络和固件执行。到期、手动接管、停止和 OTA 会废止旧视觉会话；后续 `motion` / `calibrate-forward` 必须先通过新的 `start` 建立会话。本项已通过自动化测试，物理停机时延待实机验证。

控制权租约有效期为 `60 s`。所有清理路径都会在同一租约锁内先把停止命令入队，再允许新的控制请求；不存在“清理了租约却丢失停止事件”的独立清理路径。浏览器使用每页独立的 `clientId` 和递增计数，不再以电脑时间生成序号。接管时清空旧排队运动并重置序号，旧浏览器的运动请求被拒绝；其他浏览器仍可发送停止，但不会提高当前持有者的序号门槛。

视觉识别目标和物理设备身份必须绑定。只识别、不绑定设备时，不允许自动控制机器鱼。

## 6. 公网视频配置

如果公网 WebRTC 需要穿过不同网络，Python 可以配置 STUN/TURN：

```text
FISH_WEBRTC_STUN_URL=stun:...
FISH_WEBRTC_TURN_URL=turn:...
FISH_WEBRTC_TURN_USERNAME=...
FISH_WEBRTC_TURN_CREDENTIAL=...
```

FRP 只负责把浏览器请求送到 Go，不能替代 WebRTC 的 ICE、STUN 或 TURN 配置。

键盘持续按住期间每 15 秒通过 `PATCH /api/leases` 续租；续租只接受现有持有者及其 `clientId`，不会重新申请已过期或转移的控制权。松键、切页或窗口隐藏后停止续租。认证开启时，管理员的普通运动指令同样必须持有匹配的租约；明确停止不受此限制。认证关闭且不带 `clientId` 的旧式调用仍保留兼容行为。
