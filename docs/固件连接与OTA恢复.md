# 固件连接与 OTA 恢复（1.3.2）

设备优先连接上次成功认证的服务器地址，地址保存在 NVS 中。连续 5 秒未注册后回到发现流程。重新配网或清除配置时同时清除缓存地址。Wi-Fi 配置和舵机中位不会因正常 OTA 被清除。

发现回应先于阻塞扫描处理，最近 10 秒内发出的随机数仍可用于验证延迟回应，最多保存 16 个。收到服务器发现广播时，设备额外向该服务器单播认证公告，避免依赖设备广播被路由器转发。所有服务器地址回应仍验证设备身份、随机数和 HMAC。

从启动起连续 180 秒未完成服务器注册，或正常连接后连续 180 秒未恢复注册，进入 Fish-Setup-XXXXXX 配网热点。已连接 Wi-Fi 但未连接控制器也会触发。自动进入配网不清除原配置；未配置设备仍立即进入配网。

连接热点后打开 http://192.168.4.1/ 。可以重新设置 Wi-Fi，或使用“离线固件恢复”上传适用于 XIAO ESP32-C3 的应用固件 firmware.bin。不要上传 bootloader.bin、partitions.bin 或合并烧录镜像。写入期间设备停止运动。写入失败保留当前启动分区，可重新上传；成功后重启。底层 Update/ESP-IDF 在切换启动分区时验证镜像。

服务器 OTA 下载新增 5 秒无数据超时和 120 秒总下载时限；下载期间每秒向服务器发送状态心跳，失败中止更新，不激活未完成镜像。服务器页面的回执超时不等于设备一定更新失败，最终需确认重新上线后报告的固件版本。

本地检查：

```bash
pio test -d firmware -e native
pio test -d firmware -e embedded_test --without-uploading --without-testing
pio run -d firmware -e seeed_xiao_esp32c3
```

主机测试覆盖配网倒计时、连接后断线、延迟发现回应、过期随机数、计时回绕和缓存淘汰。嵌入式测试命令只编译，不代表在开发板执行成功。

2026-09-05 首次从 1.3.1 发起 OTA：服务器记录固件下载约 19.6 秒，旧设备在下载期间没有发送心跳，控制连接被 10 秒超时关闭；OTA API 于 30 秒返回 504。升级结果需以设备重连后的版本为准。

同日实机回归：抓包确认第一次更新后的 heartbeat 报告 firmwareVersion=1.3.2。随后从 1.3.2 再次通过控制台 OTA 同一固件，下载耗时 10.237 秒，OTA API 在 11.089 秒返回 200，页面显示“开发板已确认 OTA 写入完成”。设备于完成回执约 2 秒后重新注册。该验证没有通过 USB 写入固件；USB 仅用于读取串口。

恢复实测限制：临时仅阻断设备到本机 172.16.20.140:8081/UDP 30303 的通信后，串口显示设备转连到另一个通过认证的控制器 172.16.20.189:8081。因此该场景不满足“连续三分钟未注册任意控制器”，不能据此宣称三分钟恢复已完成实机验收。临时 INPUT 阻断规则已撤销，设备重新注册回本机。离线上传页面已在浏览器检查，AP 下实际上传仍待验收。
