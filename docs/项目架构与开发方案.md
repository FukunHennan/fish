# 机器鱼系统架构

更新时间：2026-09-04

## 1. 系统目标

通过电脑上的一个 GUI 管理多台 ESP32 机器鱼，同时接入摄像头、YOLO 识别、路径跟踪和固件 OTA。

系统采用分层设计：

```text
浏览器 GUI
    │ HTTP / WebSocket / 视频
    ▼
Go 中央控制器
    ├── ESP32 机器鱼
    └── Python 视觉服务
```

核心原则：

- 浏览器不直接连接 ESP32。
- 浏览器不直接连接 Python。
- Python 不直接向固定 IP 的机器鱼发送运动命令。
- Go 是设备、视觉、权限、控制权和公网访问的统一入口。
- ESP32 只执行命令，并上报真实状态。

## 2. 模块职责

### ESP32 固件：`firmware/`

负责：

- Wi-Fi 配网和联网。
- 局域网设备发现。
- HMAC 挑战认证。
- WebSocket 注册、心跳和状态上报。
- 舵机、电机、RGB 和电池相关控制。
- 断线安全停止。
- 管理员发起的 OTA。

ESP32 不负责：

- 读取摄像头。
- 运行 YOLO。
- 计算路径和 PID。
- 判断网页用户权限。

### Go 控制器：`controller/`

负责：

- 提供 GUI 使用的 HTTP API 和 WebSocket。
- 管理登录、普通用户、管理员和控制权租约。
- 接收 ESP32 的发现、注册、心跳和状态。
- 维护每台设备的发送队列。
- 转发手动命令、视觉命令、RGB 和 OTA。
- 启动、停止和监控 Python 视觉服务。
- 代理视频和视觉接口。
- 作为 FRP 的本机目标服务。

### React GUI：`controller/frontend/`

主要入口：

```text
http://127.0.0.1:8098/
```

负责：

- 显示固定顺序的设备列表。
- 显示设备在线状态和真实运动状态。
- 申请、显示和释放控制权。
- 发送手动和视觉控制意图。
- 选择视觉识别目标与物理设备绑定。
- 显示视频、YOLO 目标、轨迹和视觉状态。
- 管理账户设置和管理员 OTA。

GUI 不根据“HTTP 请求返回成功”伪造设备已执行状态，而是等待 ESP32 的状态消息确认。

### Python 视觉服务：`vision/`

负责：

- 摄像头枚举和采集。
- YOLO 模型加载与识别。
- 机器鱼跟踪。
- 场地、鱼尾和鱼头标定。
- 坐标转换和路径绘制。
- 路径跟踪、误差计算和运动参数计算。
- 生成 WebRTC 视频，必要时回退到 MJPEG。

Python 服务只监听：

```text
127.0.0.1:8091
```

Python 产生的是视觉结果和运动意图，最终设备命令仍由 Go 检查并转发。

## 3. 运行端口

| 端口 | 服务 | 是否公网入口 |
|---:|---|---|
| 8098 | Vite React GUI | 本机开发页面 |
| 8081 | Go Controller | 是，FRP 只转发这一层 |
| 8091 | Python Vision | 否，仅本机 |
| 9998 | 视觉平板遥测 | 当前由 Python 使用，按部署需要开放 |

正式公网使用时不应把 `8091`、ESP32 地址或部署密钥暴露出去。

## 4. 设备发现和连接

```text
ESP32 联网
   │
   ├─ 每 3 秒广播 device.announce
   ▼
Go 验证 HMAC
   │
   ├─ 单播 controller.offer
   ▼
ESP32 建立 /ws/device
   │
   ├─ auth.challenge
   ├─ register
   ├─ heartbeat
   └─ command / command.result
```

设备以 MAC 地址作为 `deviceId`。注册失败、协议版本不支持或挑战证明不正确时，Go 不接受设备命令。

## 5. 三条数据链路

### 手动控制

```text
键盘/按钮
  → GUI
  → Go 控制权检查
  → Go 设备发送队列
  → ESP32 WebSocket
  → 舵机/电机
```

键盘规则由 GUI 计算动作意图：转弯优先于直行；释放转弯键后，如果 `W` 仍按下，恢复直行。切换设备、窗口失焦或页面隐藏时清空按键并发送停止。

### 视觉控制

```text
摄像头
  → Python
  → YOLO / 跟踪 / 路径 / 控制计算
  → Go 目标绑定和控制权检查
  → ESP32
```

Go 对运动命令设置独立的 3 秒有效期，设备心跳不续期；到期后排队停止并废止旧视觉会话。Python 重启后必须重新启动控制，不能恢复旧命令。

识别目标和物理设备是两个概念。识别错目标时，GUI 允许重新选择目标，再重新绑定物理设备。目标丢失、视觉会话超时、Python 异常或停止视觉时发送安全停止。

### 视频显示

```text
摄像头
  → Python 视频服务
  → Go 反向代理
  → GUI
```

视频不通过 ESP32 WebSocket 传输，也不把 Python 端口直接交给浏览器。

## 6. 控制权和权限

### 普通用户

- 查看在线设备和设备状态。
- 申请、使用和释放设备控制权。
- 进行手动运动控制。
- 使用视觉识别、目标绑定和视觉控制。
- 调整允许范围内的运动参数。
- 调整 RGB 和设备显示设置。
- 查看摄像头、视频和诊断提示。

### 管理员

在普通用户权限基础上增加：

- 管理普通用户账户。
- 处理账户状态和权限。
- 管理设备配置。
- 发起和取消 OTA。
- 执行紧急停止和运维操作。
- 查看管理员侧诊断信息。

管理员不能读取用户密码。公网环境仍需要 HTTPS、登录会话和操作日志。

## 7. 状态可信来源

GUI 状态的优先级：

1. ESP32 的 `heartbeat`、`state`。
2. ESP32 的 `command.result`。
3. Go 的连接和租约状态。
4. GUI 本地的发送中、排队中提示。

普通命令的 `sent=true` 表示 Go 已写入 WebSocket；键盘实时接口的 `sent=true, queued=true` 只表示入队；`acknowledged=true` 表示设备返回了对应结果；两者都不等于设备一直保持该动作，GUI 仍要使用后续 heartbeat 确认。

## 8. 安全停止

以下情况必须停止运动：

- ESP32 与 Go 的 WebSocket 断开。
- 控制器心跳超时。
- 视觉目标丢失或视觉会话超时。
- Python 视觉服务退出。
- 用户释放控制权。
- 管理员执行紧急停止。
- OTA 开始。

停止命令必须经过同一台设备的发送队列，避免旧的转弯或前进命令在停止之后再次写入。

## 9. 目录结构

```text
fish/
├── controller/       Go 控制器和 React GUI
├── firmware/         ESP32-C3 固件
├── vision/           Python 视觉服务和模型
├── protocol/         设备通信协议
├── config/           本机配置和 FRP 模板
├── scripts/          启停脚本
└── docs/             架构、部署、参数和维护文档
```

## 10. 当前状态与后续工作

当前已具备：

- ESP32 发现、认证、WebSocket、心跳、控制和 OTA 代码。
- Go 设备汇总、控制权、视觉进程和视频代理。
- React 手动、视觉、设置和权限界面。
- Python 无窗口视觉服务、YOLO、跟踪和视频输出。
- 前端、Go 和 Python 自动测试。

仍需现场确认：

- 真实设备长时间联网稳定性。
- 摄像头反复启动和释放。
- 多设备同时控制。
- FRP 远程视频延迟和带宽。
- HTTPS、域名、FRP 服务端和公网权限配置。
