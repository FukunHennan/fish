# 机器鱼中央控制系统五阶段开发计划

**目标：** 先完成设备端全部能力，再用简单网页逐项验证，随后迁移视觉显示和全部 VISION 功能，最后进行正式 UI 设计。

**设计文档：** `docs/superpowers/specs/2026-08-24-lan-fish-control-system-design.md`

## 第一阶段：ESP32 完整功能

### 设备基础

- [x] 将 PlatformIO 工程整理到 `firmware/`。
- [x] 主动连接路由器并将配置保存到 NVS。
- [x] 连接失败后启动带 Captive Portal 的临时配网热点。
- [x] 使用 MAC 和设备令牌注册中央控制器。
- [x] 实现 WebSocket 重连、心跳和 2 秒失联停止。
- [x] 将运动、网络、配置、身份和通信拆分为独立模块。

### 手动运动协议

- [x] 支持前进、左转、右转、停止和待机。
- [x] 支持频率和幅度设置，方向切换不覆盖参数。
- [ ] 支持显式偏置参数，而不只使用固定转向值。
- [ ] 为所有命令统一请求 ID、结果代码和错误说明。
- [ ] 上报完整设备状态：模式、参数、RSSI、IP、版本、运行时间、连接状态和最后控制时间。
- [ ] 严格拒绝错误数字、未知字段、越界参数和不支持的协议版本。

### 视觉控制协议

- [ ] 增加 `vision.start`，创建带会话 ID 的视觉控制会话。
- [ ] 增加 `vision.update`，接收递增序号、横向误差、目标距离、速度、曲率和制动请求。
- [ ] 拒绝旧会话和倒退或重复的视觉序号。
- [ ] 增加 `vision.stop`，立即废止会话并归中停止。
- [ ] 实现视觉指令超时停止，超时时间可配置但必须有安全上限。
- [ ] 明确网页手动和视觉控制的控制权切换规则。
- [ ] 根据当前硬件执行器确认并实现视觉 PID 输出。
- [ ] 上报视觉会话、最后序号、控制量、停止原因和 PID 状态。

### OTA 预留接口

- [ ] 定义 `ota.start`、`ota.cancel` 和 OTA 状态消息。
- [ ] OTA 开始前立即停止运动并拒绝新的运动会话。
- [ ] 预留固件 URL、大小、SHA-256、版本和目标板字段。
- [ ] 上报等待、下载、校验、写入、重启和失败状态。
- [ ] 当前阶段可以不实现网页上传和任务页面，但固件协议与处理入口必须存在。

### 第一阶段验证

- [ ] 在真实 ESP32-C3 上运行运动、网络和协议测试。
- [ ] 使用协议测试工具覆盖所有合法和非法消息。
- [ ] 断开控制器、Wi-Fi 和视觉消息，验证所有超时停止。
- [ ] 构建并烧录正式固件，记录 RAM、Flash 和固件哈希。

## 第二阶段：简单 Web 测试 ESP32 全部功能

- [ ] 完成最小 Go 控制器的构建和自动测试。
- [ ] 网页显示设备名称、MAC、IP、固件、RSSI、在线状态和完整运动状态。
- [ ] 网页测试前进、左转、右转、停止和待机。
- [ ] 网页测试频率、幅度和偏置。
- [ ] 网页模拟 `vision.start`、连续 `vision.update` 和 `vision.stop`。
- [ ] 网页显示请求 ID、设备确认、错误代码和超时。
- [ ] 网页测试手动与视觉控制权切换。
- [ ] 网页显示并测试 OTA 接口占位，不要求上传固件。
- [ ] 网页测试控制器断开、设备离线和紧急停止。
- [ ] 这一阶段只使用简单测试布局，不开展正式 UI 设计。

## 第三阶段：Web 显示视觉内容

- [ ] 将 `VISION.zip` 纳入项目并建立可复现 Python 环境。
- [ ] 去除硬编码解释器、相机索引和旧机器鱼 IP。
- [ ] 将 VISION 改为默认无窗口的视觉服务，并保留 `--debug-window`。
- [ ] 定义 Go 与 Python 的服务状态、视频和遥测协议。
- [ ] 在 Web 中显示 MJPEG 实时处理画面。
- [ ] 显示检测框、鱼尾位置、置信度和跟踪来源。
- [ ] 显示摄像头 FPS、YOLO FPS、处理延迟和服务错误。
- [ ] Python 不可用时，第二阶段的设备测试功能仍然可用。

## 第四阶段：Web 复现 VISION 全部功能

- [ ] Web 完成 ArUco 和手动水池四角标定。
- [ ] Web 完成鱼尾颜色区域和鱼头方向标定。
- [ ] Web 支持鼠标和触摸路径绘制、撤销和清除。
- [ ] Web 支持路径准备、启动、停止、到达终点和错误反馈。
- [ ] 将 VISION 控制量通过 Go 转发为第一阶段的视觉协议。
- [ ] Web 显示位置、速度、航向、离轨误差、目标距离、曲率、转向和制动。
- [ ] Web 支持转圈标定、标定结果保存和加载。
- [ ] Web 支持相机、YOLO、HSV、场地、控制和 PID 参数配置。
- [ ] Web 支持 CLAHE、曝光、截图、录像、CSV 和数据下载。
- [ ] Web 显示日志、停止原因、编辑锁和视觉会话状态。
- [ ] 本地调试窗口与 Web 共用状态和编辑锁，不直接控制 ESP32。
- [ ] 验证单摄像头、单目标机器鱼完整视觉闭环。

## 第五阶段：正式 UI 设计

- [ ] 以方案 A“视频工作台”为起点重新梳理正式信息架构。
- [ ] 顶部放置系统状态、当前目标和全局紧急停止。
- [ ] 左侧放置设备列表和功能导航。
- [ ] 中间以实时视频、标定和路径为主体。
- [ ] 右侧放置任务、控制参数和视觉指标。
- [ ] 完成设备、视觉配置、控制参数、录像数据、OTA 和日志页面设计。
- [ ] 完成桌面和平板响应式布局。
- [ ] 完成加载、离线、错误、危险确认和权限状态设计。
- [ ] 完成可访问性、键盘操作和触摸操作验证。

## 第五阶段之后

继续完善网页 OTA、FRP 公网安全、管理员权限、自动回滚和 Windows/macOS 正式发布。
