F机器鱼中央控制系统
四个部分 数据路径 协议范例
PROJECT IN ONE MINUTE

一条鱼，四层协作。

电脑网页负责操作，Go 负责连接和权限，Python 负责看懂画面，ESP32 负责让机器鱼真正动起来。

简单理解：上层发意图，底层做执行
THE FOUR PARTS

每一层只做好一件事

模块分开以后，换界面、换算法或换设备，不需要把整个系统一起重写。

01

ESP32：动起来

连接 Wi-Fi，完成身份认证，控制舵机、电机和 RGB，并在断线时自动停止。

02

Go：管起来

统一接收网页请求，管理设备、控制权、状态和 OTA，是系统唯一的对外入口。

03

Python：看得懂

读取摄像头，使用 YOLO 识别目标，计算路径和运动参数，再交给 Go 转发。

04

协议：说清楚

所有命令和状态使用统一 JSON。发送成功、设备收到、设备执行成功，分别表达。

UI

电脑端 GUI

实际界面位于 8098，通过 Go 控制器操作设备和视觉，不直连 ESP32。

SAFE

安全边界

公网只暴露 Go。Python、ESP32 和部署密钥留在内网，异常和失联都优先停止。

DATA ROUTE

数据是这样走的

局域网访问和远程访问使用同一套控制逻辑；FRP 只负责把 Go 的入口转发出去。

⌨
浏览器8098 / GUI
↗
FRP远程时才经过
⇄
Go 控制器8081 / 统一入口
◉
Python8091 / 视觉服务
🐟
ESP32WebSocket / 执行

本地访问：浏览器 → Go。远程访问：浏览器 → FRP → Go。视觉和设备都由 Go 分别转发：摄像头 → Python → Go → ESP32。

PROTOCOL EXAMPLE

协议长什么样

网页只表达意图

网页说“让 1 号鱼前进”，Go 检查登录、控制权和设备在线状态，再把统一命令发给 ESP32。

设备返回真实结果

ESP32 执行后返回同一个 requestId，GUI 用后续状态确认设备当前动作。

{
  "type": "command",
  "requestId": "req-1024",
  "command": "motion.set",
  "payload": {
    "deviceId": "A4:CF:12:34:56:78",
    "controlSource": "manual",
    "mode": "forward",
    "frequency": 2.5,
    "amplitude": 28,
    "bias": 0
  }
}

ESP32 收到后返回 command.result，并持续发送 heartbeat；控制器心跳超时，设备会归中停止。
