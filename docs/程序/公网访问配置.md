# Windows 公网访问：Cloudflare Tunnel

本页适用于 Pro1 的 Windows 启动入口 `scripts\start.bat`。Cloudflare Tunnel 将公网 HTTPS 请求转发至本机 Go 控制器 `http://127.0.0.1:8081`；Python 视觉服务和 ESP32 不需要单独暴露端口。Linux/macOS 的 `scripts/start.sh` 不负责启动 Tunnel，需自行管理 `cloudflared` 服务。

> **当前部署启用内建登录。** `FISH_AUTH_DISABLED=false` 要求本地和公网用户登录。只有账号 `3` 能进入裁判页面；Cloudflare Tunnel 负责转发请求。不要把隧道凭据、`cert.pem` 或密码提交到仓库。

## 1. 准备本机和 Cloudflare

- 本机能运行 Go、Node/npm、Python，且 `scripts\start.bat` 启动后可以访问 `http://127.0.0.1:8081/competition.html`。
- 拥有在 Cloudflare 管理的域名及对应 DNS 修改权限，Windows 主机可以连接 Cloudflare 网络。
- 下载适用于 Windows 的 `cloudflared.exe`，放在 `controller/.runtime/cloudflared.exe`；首次配置可从项目根目录运行 `controller\.runtime\cloudflared.exe --version` 确认程序可执行。

新电脑可先运行 `scripts\setup.bat` 安装电脑端依赖；当 `tunnel.json` 已启用时，脚本会尝试安装并放置 `cloudflared.exe`。隧道凭据仍须在新电脑上单独准备并更新 `credentialsFile`，安装脚本不会复制旧电脑的私有凭据。只先验证本地服务时可运行 `scripts\setup.bat --local --cpu`。

以下命令在 **Pro1 项目根目录的 PowerShell** 执行。如果已经有本机可用的命名隧道及其 JSON 凭据，可跳过创建步骤，直接使用已有 UUID 和凭据文件；只有 `cert.pem` 不能代替运行隧道所需的 `<UUID>.json`。

```powershell
.\controller\.runtime\cloudflared.exe tunnel login
.\controller\.runtime\cloudflared.exe tunnel list
.\controller\.runtime\cloudflared.exe tunnel create fish-controller-windows
```

`login` 会打开浏览器，请登录 Cloudflare 并授权实际托管目标域名的区域；授权后本机用户目录下出现 `$env:USERPROFILE\.cloudflared\cert.pem`。`create` 输出隧道 UUID，并在同一目录创建 `<UUID>.json`。记下这两个值，不要复制 JSON 内容到 `tunnel.json`。已有同名隧道时不要重复创建，先通过 `tunnel list` 和本机凭据文件核对。

## 2. 选择访问模式

当前 `config/program.json` 设置为 `"FISH_AUTH_DISABLED": "false"`：本地与公网都要求项目账号登录。进程环境变量优先于 JSON；修改配置后必须重启 Go 控制器。账号数据保存在运行机器的用户配置目录中。

如果另行启用 Cloudflare Access，应验证隧道域名的访问边界；不要把 `FISH_TRUST_CF_ACCESS` 设置为 `true`，除非已确认可信代理会清理伪造请求头。
## 3. 配置域名和 `tunnel.json`

将 `<UUID>` 和 `<你的域名>` 换成自己的值。先创建指向隧道的 DNS 路由：

```powershell
.\controller\.runtime\cloudflared.exe tunnel route dns <UUID> <你的域名>
```

如果提示同名 A、AAAA 或 CNAME 记录已存在，先在 Cloudflare DNS 中核对原记录的用途。**只有确认要用新隧道替换这个域名时**，才运行 `tunnel route dns --overwrite-dns <UUID> <你的域名>`；这会覆盖现有记录。

编辑 `config/tunnel.json`：

```json
{
  "enabled": true,
  "tunnelId": "<UUID>",
  "credentialsFile": "C:\\Users\\<Windows用户名>\\.cloudflared\\<UUID>.json",
  "hostname": "<你的域名>",
  "service": "http://127.0.0.1:8081"
}
```

`enabled` 必须为 JSON 布尔值（不是字符串）。`tunnelId` 是 `create` 输出的 UUID；`credentialsFile` 必须指向**运行程序的同一 Windows 用户**能读取的 `<UUID>.json`，可用绝对路径或相对 Pro1 根目录的路径，JSON 中反斜杠需写成 `\\`；`hostname` 不带 `https://`；`service` 指向本机 Go 控制器。不要把凭据 JSON 放到项目目录或提交到 Git。若复制到另一台电脑，必须单独准备凭据和适合新用户的路径。

## 4. 启动和验证

关闭旧启动窗口，重新运行 `scripts\start.bat`。脚本构建前端和 Go，依据 `tunnel.json` 生成 `controller/.runtime/cloudflared-live.yml`，再启动 `cloudflared` 和控制器。窗口关闭时，其启动的服务也会停止。公网浏览器访问 `https://<你的域名>/competition.html`，使用账号登录。

```powershell
Invoke-RestMethod http://127.0.0.1:8081/api/auth/me
Invoke-RestMethod https://<你的域名>/api/auth/me
```

当前登录模式下，未登录时两处都应显示 `authenticated: false`，受保护接口返回 HTTP 401；裁判页面只接受账号 `3`。可从手机移动网络测试，避免仅验证本机网络。

## 5. 跨网视频 TURN

Cloudflare Tunnel 只转发网页、API 和 WebRTC 信令，不能替浏览器转发 WebRTC 媒体。当前现场电脑只有内网 IPv4，没有可直接从异网访问的公网地址，因此优先使用 [Cloudflare Realtime TURN](https://developers.cloudflare.com/realtime/turn/)。本机实测可访问 Cloudflare TURN 的 TCP 443，STUN UDP 3478 有响应；这只能证明服务端出口可达，不能替代异网媒体验收。[Cloudflare 官方说明](https://developers.cloudflare.com/realtime/turn/faq/)指出中国网络不承载 Realtime TURN，中国的 TURN 流量会连接境外节点，因此仍需实测延迟。Cloudflare 账号需先开通 Realtime 订阅；控制台当前显示每月 1,000 GB 免费，超出后按量计费，开通需要付款方式。此步骤由账号持有人亲自完成。

在 Cloudflare Realtime 的 TURN 页面创建一个 TURN Key，记下 Key ID 和只显示一次的 API token。不要把长期 token 填入 `config/program.json`、命令行参数、聊天或 Git。于 Pro1 根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/runtime/set-turn-key.ps1 -KeyId <Key ID>
```

脚本会隐藏输入 token，写到项目外的 `../Pro1-runtime/cloudflare-turn-key.json`，并限制当前 Windows 用户读取。视觉服务读取该文件后向 Cloudflare 换取 24 小时有效的临时 ICE 凭据；浏览器只能收到临时凭据。TURN Key 变更后，新视频连接会自动读取新文件。旧的静态 `FISH_WEBRTC_TURN_URL`、`FISH_WEBRTC_TURN_USERNAME`、`FISH_WEBRTC_TURN_CREDENTIAL` 仅用于未安装 Cloudflare Key 的部署。

用另一网络上的已登录选手页面测试：画面状态应从“公网兼容模式”变为 WebRTC 连接，连续观察首帧、延迟与控制响应。服务端 `GET /api/vision/webrtc/config` 只允许已登录的对应用户访问，返回的 `iceServers` 应包含 `turn.cloudflare.com`，但绝不能包含长期 token。若仍回退兼容画面，应排查 Cloudflare Key、TURN 连通性与浏览器 ICE 日志；不能仅凭配置信息认定媒体中继已成功。

## 常见问题与维护

- **公网 530、隧道离线**：核对 DNS 路由 UUID、`enabled`、`credentialsFile`、`controller/.runtime/cloudflared.err.log` 中是否出现 `Registered tunnel connection`，并确认启动窗口持续运行。
- **本地 8081 不通或公网 502**：先排查控制器是否启动、端口是否被其他进程占用，再核对 `service`；浏览器页面可加载不代表控制器和视觉服务均正常。
- **公网未登录时仍有管理员权限**：检查进程环境变量是否覆盖了 `config/program.json` 中的 `FISH_AUTH_DISABLED=false`，修正后重启控制器。
- **登录电脑后服务未启动**：本项目不创建开机或登录计划任务。需要使用时，在 Pro1 目录手动运行 `scripts\start.bat`，并保持启动窗口打开。
- **视频跨公网不稳定**：先按第 5 节开通 TURN 并异网验收。WebRTC 首帧仍失败时，页面优先用隧道内的一条 WebSocket 持续发送最新 JPEG 帧，连接失败再改用 HTTPS 单帧轮询。兼容画面采用 `480×360`、JPEG 质量 58；实际帧率取决于现场网络。

只想本地运行时，把 `enabled` 改为 `false` 并重新启动；不要删除管理员用户库或隧道凭据。当前部署机器的 UUID、域名和路径可查看 [`config/tunnel.json`](../../config/tunnel.json)，但文件存在不表示当前公网服务一定在线。
