- 监控使用本次启动保存的 PID，不再读取可能被下一次启动覆盖的共享 PID 文件。退出助手同时验证 PID 文件与可执行文件路径，避免旧窗口误停新服务。
- 增加视频健康检查告警，纠正 Python 日志位置提示。视频健康告警不会擅自终止设备控制服务。

- `vision/webrtc.py`：凭据获取转移到线程，避免同步网络请求或锁等待阻塞现有视频事件循环。
- `controller/frontend/src/VideoStream.jsx`：ICE 收集超时明确失败，不再把不完整 Offer 当作成功提交；连接总超时调整到 30 秒。继续强制 TURN，这是用户要求，不作为直连配置缺陷处理。
- 比赛页：裁判切换全画面与裁剪画面时通过 `/webrtc/view` 更新同一视频轨道，复用视频元素；隐藏的画面不触发无帧重连。
- Go 注册测试：等待异步登记完成，保留服务端先发送注册确认、再开放控制的协议顺序。

## 本轮后续修复

下列四项高优先级问题及其他比赛/视觉进程问题已修复。每个操作先检查持久化结果；结束比赛的归档与下一场状态只写入一次，失败保留原比赛供重试。录像停止结果在失败重试期间暂存，避免重复停止录像。

### 已修复：比赛数据保存失败未上报

`controller/internal/web/competition.go` 的计分和结束路径忽略 `saveLocked` 错误。磁盘满、权限错误或重命名失败时，界面仍可能显示成功；结束后还会清零并进入下一场。应先持久化完整归档与下一场状态，失败时保留可重试状态并返回明确错误。

### 已修复：进行中比赛的重启恢复不一致

运行期间每秒保存计时检查点；重启后按最近成功检查点恢复为暂停，保留比分、事件和阵容，不把停机时间算入比赛。录像标记为中断；用户恢复比赛时重新启动录像。磁盘故障期间不能保证新的检查点落盘，会记录错误。

`competitionStore` 的 `started/running` 未持久化；保存的 `state=running` 重启后可能与内存计时器及录像状态不一致，导致界面显示进行中却不能计分。应设计明确的重启恢复状态及计时检查点，并核实录像服务是否仍在录制。

### 已修复：重复结束请求归档空比赛

结束接口现在要求 `matchId`。已归档 ID 再次结束直接返回当前状态；ID 不匹配或比赛未开始时拒绝操作。前端绑定当前比赛 ID，并保留明确提供的重试 ID。

结束会立即生成新的 ready 比赛，但结束接口未按目标比赛 ID 幂等处理。双击、请求重试或多个裁判可能将新比赛再归档。应让请求携带目标比赛 ID，并由服务端按该 ID 幂等处理。

### 已修复：选手租约模式绕过设备分配校验

租约获取、续期及普通/实时命令均根据已认证账号校验当前战队设备归属；手动或其他模式不能绕过，旧租约也不能继续控制对方设备。管理员权限保留。

`controller/internal/web/server.go` 的租约入口仅对客户端声明的 player 模式校验选手席位。选手可提交 manual 模式绕过校验。应根据已认证账号角色与设备归属验证，不让客户端模式决定权限。

### 仍需评估的视频实现限制

- 已安装 aiortc 只选择一个有效 TURN URL，不能假设 URL 列表能自动在服务端尝试所有 UDP/TCP/TLS 通道。
- 当前服务端 relay 使用信令候选过滤；底层 aioice 仍可能保留 host 协议参与候选配对。此前实测为 relay/relay，但过滤 SDP 本身不能保证所有网络条件下的服务端媒体都经 TURN。应在实际 ICE 配对层约束并增加验证，避免未经测试直接修改依赖内部实现。
- 本机 TURN 测试只代表服务器电脑网络，不代表远端用户网络；短测通过不能证明长期无重连。

### 其他已修复的行为

- 到时由后端计时任务独立结束；计分入口也检查截止时间，拒绝超时得分。
- 旧记录加载时为重复/空 ID 分配不冲突的标识，支持逐条删除，并保留仍被其他记录引用的录像。
- 删除最新记录同步清理 LastFinished 与通知领取状态；元数据保存失败时不删除录像。保存成功后录像清理失败会返回明确警告，供管理员后续处理。
- 外部视觉后端不健康时返回不能自动接管的错误，不再启动端口冲突的新进程；自有后端仍可由守护逻辑恢复。
