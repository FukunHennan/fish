# Fish 项目环境与构建/烧录说明

本文档根据仓库中的配置、代码和脚本记录构建与烧录流程。摄像头能力、串口号、Cloudflare Tunnel 和外部服务状态需在运行机器上核对。

## 1. 系统组成

| 组件                | 目录                                                                               | 作用                                                 | 地址/端口            |
| ----------------- | -------------------------------------------------------------------------------- | -------------------------------------------------- | ---------------- |
| Go 控制器            | `controller/`                                                                    | 设备注册、控制、租约、OTA、SSE                                 | `0.0.0.0:8081`   |
| 赛事前端              | `controller/frontend/competition.html`、`controller/frontend/public/competition/` | 原生 HTML/CSS/JavaScript 正式界面；`src/` 下 React 代码为历史实验 | 由 `8081` 提供      |
| Python 视觉         | `vision/`                                                                        | 摄像头、识别、WebRTC 信令                                   | `127.0.0.1:8091` |
| ESP32-C3 固件       | `firmware/`                                                                      | Wi-Fi、设备 WebSocket、运动、电池、配网、OTA                    | 连接控制器 `8081`     |
| 局域网发现             | 固件/控制器                                                                           | UDP 发现控制器                                          | `30303/UDP`      |
| Cloudflare Tunnel | Windows 启动脚本使用 `controller/.runtime/` 下的程序与配置；此前 Linux 部署使用仓库外的 systemd 用户服务     | 公网转发到 Go 控制器                                       | 由实际隧道配置决定        |

控制命令使用浏览器到控制器的 `/ws/control`，再由控制器通过 `/ws/device` 下发到 ESP32；设备状态通过 `/api/events` SSE 推送。视频走视觉服务的 WebRTC 链路。

## 2. Windows 开发工具

项目根目录以当前检出的 `Pro1/` 目录为准；下文命令均从该目录执行。

### 新电脑只有 Node.js 时

需要 Windows 自带的 PowerShell、`winget`（Windows App Installer）和网络连接；Node.js 必须包含 npm，版本满足 `20.19+` 或 `22.12+`。在项目根目录执行：

```bat
scripts\setup.bat --local --cpu
scripts\start.bat
```

`setup.bat` 调用 `scripts/bootstrap/setup-windows.mjs`：检测并通过 `winget` 安装 Go 1.23+ 和 Python 3.12，在 `vision/.venv` 安装 `requirements.txt`，执行前端 `npm ci`、构建前端和 Go。`--local` 将 `config/tunnel.json` 的 `enabled` 改为 `false`；`--cpu` 将 `config/program.json` 的 `FISH_YOLO_DEVICE` 改为 `cpu`，适合没有隧道凭据或 GPU 的新电脑，CPU 推理性能需实测。两个选项只在明确指定时改动配置。运行 `scripts\setup.bat --check` 可只查看基础依赖与隧道文件，不安装或改动文件。

本分支保存运行日志、录像和账号迁移快照；`vision/.venv`、`controller/frontend/node_modules` 及可重新下载或构建的程序不进入 Git。新电脑从 Git 克隆或下载 ZIP 后，仍用上面的 `setup.bat` 安装 Go、Python、前端及视觉依赖，并构建本机程序。

若保留启用的隧道配置，不加 `--local` 时安装脚本会尝试通过 `winget` 安装 `cloudflared` 并复制到 `controller/.runtime/`；隧道 JSON 凭据是电脑和用户专有文件，必须自行准备并更新 `credentialsFile`，缺失时安装脚本会以失败状态提示。需要在新电脑编译固件时加 `--firmware`，脚本会在 `%USERPROFILE%\.platformio\penv` 安装 PlatformIO Core 6.2.x 并构建固件，不会自动烧录。首次安装可能下载较大的 Python、PyTorch 和固件工具链；系统安装程序可能请求管理员确认。

安装成功仅表示依赖和电脑端构建通过。启动后还需核对相机枚举编号、USB 采集模式、GPU/CPU 推理、ESP32 Wi-Fi、视觉健康接口和画面。当前账号库由 `config/program.json` 指向 Pro1 同级的 `Pro1-runtime/`；本分支在 `controller/.runtime/users.json*` 保存了一份快照，首次使用 `scripts/start.bat` 时若同级数据目录为空，启动脚本会迁移这份快照。完整启动状态不能由 `--check` 代替验证。

- Python：视觉服务依赖由 `vision/requirements.txt` 管理。
- Node.js/npm：前端依赖由 `controller/frontend/package-lock.json` 管理。
- Go：`controller/go.mod` 要求 Go `1.23`。
- PlatformIO：`environment-build.ps1` 优先使用 `PATH` 中的 `pio`，找不到时使用 `%USERPROFILE%\.platformio\penv\Scripts\pio.exe`。
- Git：只用于版本管理；构建和烧录不会自动提交或推送。
- GPU 推理：当前机器使用 NVIDIA RTX 3050；`nvidia-smi` 应能看到显卡，视觉虚拟环境必须安装 CUDA 版 PyTorch，不能使用 `+cpu` 版本。

在同一个 PowerShell 会话中先检查环境并设置 `$pio`，后续固件命令沿用该变量：

```powershell
python --version
node --version
npm --version
go version
$pio = (Get-Command pio -ErrorAction SilentlyContinue).Source
if (-not $pio) { $pio = Join-Path $env:USERPROFILE '.platformio\penv\Scripts\pio.exe' }
& $pio --version
```

不要在同一构建目录混用不同的 PlatformIO 安装。`environment-build.ps1` 使用 `PATH` 中的 `pio`，找不到时才使用用户目录下的 `pio.exe`；检查版本时应使用与构建时相同的可执行文件。

## 2.1 更换电脑或显卡后的 YOLO 检查

更换电脑、显卡或重建 `vision/.venv` 后，先检查驱动和 PyTorch：

```powershell
nvidia-smi
& .\vision\.venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.device_count()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'no CUDA GPU')"
```

若版本带 `+cpu`、`torch.version.cuda` 为 `None` 或 `cuda.is_available()` 为 `False`，安装与 Python 版本匹配的 CUDA wheel。下面是 CUDA 12.8 示例：

```powershell
& .\vision\.venv\Scripts\python.exe -m pip install --force-reinstall torch==2.11.0+cu128 torchvision==0.26.0+cu128 --index-url https://download.pytorch.org/whl/cu128
& .\vision\.venv\Scripts\python.exe -m pip install "setuptools<82"
```

项目默认 `FISH_YOLO_DEVICE=0`，表示第一块 CUDA GPU；不要填写显卡名称。修改依赖后重启 `scripts\start.bat`，进入视觉识别流程，再在 `/api/vision/sessions/current` 查看 `data.metrics.yolo.ready`、`device`、`loadSeconds` 和 `inferFps`。当前机器验证为 RTX 3050、CUDA 可用、`device: 0`、YOLO ready。

## 3. 软件编译

一键构建：

```powershell
.\environment-build.ps1
```

按需跳过阶段：`-SkipPython`、`-SkipFrontend`、`-SkipFirmware`、`-SkipController`。

`environment-build.ps1` 将 Go 构建产物写为 `controller/fish-controller-v2.exe`；`scripts/start.bat` 另行构建并运行 `controller/.runtime/fish-controller.exe`。使用前者不会自动替换后者。

前端：

```powershell
cd controller/frontend
npm ci
npm run build
```

Go 控制器：

```powershell
cd controller
go mod download
go build -o .runtime/fish-controller.exe ./cmd/fish-controller
```

ESP32 固件：

```powershell
cd firmware
& $pio run -e seeed_xiao_esp32c3
```

固件产物位于 `firmware/.pio/build/seeed_xiao_esp32c3/`：`firmware.bin`、`bootloader.bin`、`partitions.bin`、`firmware.elf`。当前固件版本为 `2.0.0`，定义在 `firmware/include/AppConfig.h`。

## 4. 硬件连接

目标板为 Seeed XIAO ESP32-C3 / 按 XIAO 焊盘对齐的 ESP32-C3 Super Mini：

| 功能       |           GPIO | 说明               |
| -------- | -------------: | ---------------- |
| 舵机信号     |        `GPIO2` | 原 XIAO `D8`，一个舵机 |
| 电池采样     | `GPIO4` / ADC1 | 原 XIAO `A0`，分压中点 |
| 板载状态 LED |        `GPIO8` | 单色、高电平点亮；不是 RGB  |
| BOOT 按键  |        `GPIO9` | 低电平有效，长按 3 秒     |

电池参数：分压比 `3.0`、空电参考 `7.0 V`、满电参考 `7.4 V`、采样周期 10 秒。硬件不支持 RGB、光感和 I2C 传感器。设备唯一标识始终是 MAC，昵称仅用于前端显示。

## 5. 串口烧录

查询端口：

```powershell
Get-CimInstance Win32_SerialPort | Select-Object DeviceID,Name,Description
& $pio device list
```

编译并烧录（将 `COM19` 替换为实际端口）：

```powershell
cd firmware
& $pio run -e seeed_xiao_esp32c3 -t upload --upload-port COM19
```

PlatformIO 会写入 bootloader、分区表和应用镜像，并逐段校验。成功标志是 `Hash of data verified.` 和 `SUCCESS`。烧录后设备会自动复位；烧录时关闭串口监视器和其他 PlatformIO 进程。

OTA 接口只接受与当前源码一致的应用 `firmware.bin`，不能上传 `bootloader.bin`、`partitions.bin` 或旧镜像。

## 6. 运行检查

Windows 的 `scripts/start.bat` 是启动入口，读取 `config/firmware.json`、`program.json` 和 `tunnel.json`，并通过 `watch-controller.ps1` 监督 Go 控制器。只有 `tunnel.json` 启用时才需要在 `controller/.runtime/` 准备 `cloudflared.exe`；启动脚本会从 JSON 生成 `cloudflared-live.yml`。再次启动时，入口会先接管并关闭上一实例的启动监督窗口、控制器、视觉服务和 Tunnel，等待 `8081` 与 `8091` 释放后只启动一个新实例；不属于本工作区的端口占用不会被强制关闭。监督脚本在控制器退出后等待 5 秒重新启动；关闭启动窗口时，入口停止它启动的 Cloudflare Tunnel 并退出。启用隧道时脚本会临时写入 `controller/.runtime/cloudflared.pid`，用于跟踪隧道进程。

```powershell
scripts\start.bat
Invoke-WebRequest http://127.0.0.1:8081/healthz
Invoke-WebRequest http://127.0.0.1:8091/health
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 8081,8091 }
```

设备在线必须同时满足 Wi-Fi 已连接、v2 HMAC 注册成功、设备 WebSocket 已建立并持续回报心跳。仅检测到 COM 端口或 UDP 发现包不代表设备已经可控。

## 7. 故障排查

### `.pio/build` 文件消失

比较两套工具链：

```powershell
python -m platformio --version
& $pio --version
```

如果来源不同，停止使用旧命令，只使用标准 `pio.exe`，再执行一次完整构建。

### 找不到串口或无法烧录

检查 USB 数据线、设备管理器中的 COM 号，以及是否被 Arduino IDE/串口监视器占用。ESP32-C3 USB-Serial/JTAG 常见 VID/PID 为 `303A:1001`。必要时使用 GPIO9 BOOT 按键进入下载模式。

### 烧录成功但服务器离线

继续检查设备 Wi-Fi、控制器 `8081`、v2 版本和日志事件 `device_connected` / `device_register_rejected`。串口烧录成功只代表 Flash 校验通过，不代表网络注册成功。

## 8. 变更纪律

- 当前协议为 v2-only。
- 设备命令唯一键为 MAC，昵称不参与路由。
- 修改 GPIO、版本号、网络策略或协议后必须重新编译并重新烧录。
- 构建、烧录不执行 Git commit/push。
