# 从 Pro2 embedding 迁移到 Pro1

每次构建生成唯一的 `2.0.3-时间-随机标识` 版本，并生成 `firmware.manifest.json`。版本中的构建时间采用 UTC；镜像身份以 ESP 应用描述中的 ELF SHA-256 指纹核对。注册时上报实际运行分区的指纹。管理员 OTA 收到 `OTA_STARTED` 只代表开始，需在 120 秒内看到新 bootId、目标版本和目标构建指纹一致才确认成功；离线、回滚或不匹配均不报告完成。旧设备可接收新固件，但旧镜像没有指纹时不能提供此完成核验。文件 SHA-256 用于下载完整性，与 ELF 构建指纹不是同一字段。

上电初始化不主动输出回中 PWM，信号脚保持低电平，避免低电反复重启时反复驱动回中。停止和失联停止直接解除 PWM，不强制尾巴回中；此时舵机不主动保持位置。中位校准命令仍明确驱动回中。首次运动仍可能从实际当前位置移向目标角度。取消开机回中不能解决欠压复位或舵机自身供电异常，仍需检查电池与供电。

当前固件不内置 Wi-Fi 账号：首次启动且没有 Pro1 保存配置时直接进入 AP 配网。已保存的 Pro1 Wi-Fi 配置仍会保留；OTA 不会强制清除它。需要重新配网时长按 BOOT 约 3 秒，松开后重启。

运动默认不再渐变（`transitionMs=0`），振幅和偏置在下一个运动更新周期直接采用目标值，正常更新周期为 20ms。安全停止与失联停止保持不变。旧 Pro1 固件拒绝 `transitionMs=0`，请先升级对应设备再启用新版控制器；没有升级的设备应保持至少 100ms 的设备过渡配置，避免运动指令被拒绝。快速切换方向可能增加机械冲击，首次测试采用小振幅。

仅上传 `.pio/build/seeed_xiao_esp32c3/firmware.bin`，不要上传 ELF、bootloader、partitions 或合并烧录镜像。

Pro2 的 `/update` 接受 Basic 认证的 multipart 文件字段 `firmware`；`/ota_upload` 接受原始应用二进制及 `X-OTA-Password` 请求头。使用设备当前运行的 Pro2 页面及其凭据，不能使用 Pro1 新固件的密码替代旧设备密码。

Pro2 使用 ESP-IDF 的 `esp_ota_end` 标准镜像校验，应用分区和请求体上限为 `0x180000`（1572864 字节）。Pro1 构建后检查 ESP32-C3 镜像类型、大小、段校验和及 SHA-256，不修改或绕过校验。OTA 不会替换旧设备分区表或 bootloader。

Pro2 bootloader 启用了回滚。Pro1 在本机基础初始化完成后确认待验证应用，不等待服务器上线，避免设备因服务器离线而无法确认固件。此确认不代表网络和外设已全部通过实机测试。

若旧设备在上传阶段返回失败，需要旧设备的串口日志或 HTTP 错误内容确定原因；新固件尚未执行，无法修复旧设备的认证、接收超时、分区状态或供电问题。若上传成功但重启后退回旧版本，重点检查启动日志与回滚状态。没有实际设备上传验证时，构建成功不能视为 OTA 已成功。
